## CMS 데이터 계약

현재 lib/content.ts 배열이 데이터 원본이며 실제 관리자 CMS/DB는 구현하지 않았다. 화면과 데이터가 분리되어 API 또는 CMS로 교체할 수 있다.

Guide: slug, category, title, excerpt, keyword, vehicle?, region?, tag, sections[{title, body}], status(sample/draft/published), image?, publishedAt?, updatedAt?, author?, reviewedBy?, sources?를 갖는다.
Vehicle: slug, brand, name, type, note, guide. Region: slug, name, areas, note.
본문 확장은 sections를 텍스트/이미지/표/체크리스트 블록으로 바꾸는 방향이 적합하다. 상세 레이아웃에는 H1, 카테고리, 요약, 목차, 본문 H2, 상담 체크, 관련 글, 문의 CTA가 있다.

제목 규칙: 구체적인 차종/지역/증상 + 출장 배터리 교체 + 실제 질문 또는 확인할 항목. 예: 그랜저 출장 배터리 교체, 연식만 알려주면 될까요? 부풀린 최저가, 확정하지 않은 도착 시간, 허위 후기나 평점은 사용하지 않는다.

## SEO와 공개 전 조건

현재 비공개 UI 시안이며 noindex, robots 전체 차단, 빈 sitemap이다. 고유한 title/description/canonical 및 상세별 OG/X 필드 구조가 구현되어 있다. 상세 글에 대표 이미지가 없으면 사이트 공통 이미지를 상속하지 않는다. 글별 대표 이미지와 출처를 넣은 뒤 검수하여 published로 전환한다.

isPreview=false는 UI 시안 표기 제거, 연락 채널, 서비스 범위, 사업자 정보, 정책, 실제 콘텐츠 검수 완료와 함께 수행한다. 실제 공개 전 draft/sample 글 라우트 노출 필터와 개별 noindex 규칙을 적용하고, 확정 정보에 한해 Business/Article/Breadcrumb 구조화 데이터를 추가한다. 현재 허위 업체 사실을 만들지 않기 위해 사업자/평점 구조화 데이터는 생성하지 않았다.

## 연락과 데이터

lib/site-config.ts의 phone, kakaoUrl은 미설정. 전화/카카오 버튼은 연결 준비 안내로 이동한다. 설정 후 전화는 tel: 링크, 카카오는 확인된 채널 URL로 연결된다. 홈과 문의 페이지는 동일한 체크형 폼을 사용한다. 차종·연식만 필수이며 지역·증상·사진은 선택이다. 문구는 “체크하고 문자 보내기”와 “이 내용으로 문자 보내기”로 통일했다. phone 설정 시 sms 링크에 내용을 채워 문자 앱을 열며, 최종 전송은 사용자가 문자 앱에서 직접 한다. 현재 수신번호 미설정으로 안내와 복사만 제공한다. 사진 체크는 첨부 준비 표시이며 사진 파일은 문자 앱에서 직접 첨부한다. 입력·사진을 서버에 저장하지 않는다.

WebMCP stage_battery_inquiry는 지원 브라우저에서 동일한 폼의 차종과 지역만 채운다. 전송/예약하지 않는다. 지원 컨텍스트가 없어 계약 실행 검증은 하지 않았으며 일반 UI와 독립적으로 선택 적용된다.
